프레임 분산 GPU 압축

ASTC와 BC7은 프레임마다 일부 블록 행만 압축할 수 있습니다. 앞선 묶음의 GPU fence가 남아 있으면 다음 제출을 미룹니다. 전체 행을 제출한 뒤 텍스처로 한 번 복사합니다. 처리 중에는 이전 완성 텍스처를 계속 표시합니다.

분산하면 한 번에 제출하는 GPU 작업은 작아지고, 결과가 갱신되는 간격은 길어집니다. 행 수는 엄격한 ms 제한이 아닙니다. 입력 스냅샷과 마지막 텍스처 복사도 GPU 작업입니다. 여러 객체의 예산은 각각 적용됩니다.

일괄 압축과 행 묶음 비교

1024×1024 알파 UI와 비알파 사진 각 1장, 총 2개 대표 입력입니다. 기존 60개 품질 표본 전체를 다시 측정한 결과가 아닙니다. 모든 행 묶음을 측정해 복잡한 부분의 최대 비용도 포함했습니다.

품질블록 행/제출최소 제출 횟수일괄 ms묶음 평균 ms묶음 P95 ms묶음 최대 ms

각 품질은 최소 200ms 사전 실행하고, 각 행 범위도 2회 준비합니다. 같은 GPU 버퍼에 4회 제출한 뒤 한 번 readback으로 완료를 기다립니다. 이를 3묶음 측정한 중앙값을 사용합니다. readback 비용 일부가 포함된 처리량이며 GPU timestamp나 실제 프레임 지연이 아닙니다. 스냅샷·최종 네이티브 텍스처 복사·렌더링은 이 시간에서 제외했습니다. 최소 제출 횟수에는 GPU 대기와 스냅샷·완료 확인 프레임을 더해야 합니다. 모바일 기기 시간은 측정하지 않았습니다.

사용 방법

기존 AstcGpuStream·Bc7GpuStream에서 Spread Across Frames를 켜고 Block Rows Per Frame을 지정합니다. 기본값은 4행입니다. Snapshot Input은 기본으로 켭니다. 1024의 4×4 형식은 4행씩 최소 64번, 32행씩 최소 8번 제출합니다.

// output은 AstcGpuTexture 또는 Bc7GpuTexture입니다.
// Update에서 한 번 호출합니다.
if (!output.IsEncoding)
    output.BeginEncode(source, quality: Bc7Quality.HighQuality);
bool completed = output.EncodeNextFrame(maxBlockRows: 4);
float progress = output.EncodingProgress;

ASTC는 AstcQuality를 사용합니다. 입력은 시작할 때 같은 형식의 GPU RenderTexture에 복사합니다. 원본 값이 이후 바뀌어도 이번 결과는 캡처한 입력으로 완성합니다. 원본 객체는 완료까지 유지합니다. snapshotInput:false이면 입력 값을 완료까지 변경하지 않습니다. RGBA8 1024 스냅샷은 약 4MiB를 추가로 사용합니다. 재사용 BeginEncode·EncodeNextFrame에는 CPU readback과 Apply가 없습니다.

작업 중 quality·색 공간 설정은 시작값을 유지합니다. 완료 전 새 BeginEncode·EncodeFrame 호출은 거부합니다. 중단할 때는 마지막 소비자의 그리기 제출 후 Dispose합니다. 입력 스냅샷과 출력 자원은 GPU fence 뒤에 해제합니다. ASTC의 모바일 직접 복사는 Android Vulkan·iOS Metal에서 실기 검증이 남아 있습니다.
